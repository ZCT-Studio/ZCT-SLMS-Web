# API 概览

接口前缀为 /api/v1。常用分组如下，具体权限以接口为准：

- /auth/*：登录、注册、身份绑定及安全验证；部分接口要求已登录。
- /admin/*：管理员操作；支持账号仅使用其被授权的工单、审查等入口。
- /app/*、/license/*：按账号角色和应用归属授权。
- /tickets/*、/vouchers/*、/accounts/*：按账号与记录可见范围授权。
- /client/*：客户端授权验证，按应用配置校验签名、编码和防重放字段。

成功响应 code 为 0；失败时结合 code 与 message 判断原因，不能仅凭 HTTP 200 判断成功。
{"code":0,"message":"OK","data":{}}

已登录接口使用登录返回的 token：
Authorization: Bearer <登录接口返回的 token>

敏感操作另需完成统一身份验证；普通登录 token 不能代替操作授权。部分登录响应要求继续完成双重验证或首次账号设置。

常用接口使用 GET/POST。GET 参数放在查询字符串中，POST 推荐 application/json；其他格式以具体接口为准。

# POST /api/v1/client/license/verify

验证或激活卡密，返回当前状态、剩余时长及绑定模式。

公共字段：
- appid：应用 ID，字符串。
- timestamp：Unix 秒级时间戳，须在服务端允许的时间窗口内。
- nonce：每次请求使用新的随机字符串，长度 1–128。
- signature：应用开启请求签名时提供，按当前签名规则计算。

业务字段：
- license：卡密明文。
- device：设备标识，绑定设备的卡密需要提供。

应用启用编码或加密时，将业务字段按配置处理后放入 encode；appid、timestamp、nonce 等公共字段保持在外层。未启用时直接提交业务字段。不要使用演示密钥或在网页中公开应用密钥。

示例响应（仅用于说明字段）：
{
  "code": 0,
  "message": "OK",
  "data": {
    "status": "active",
    "remaining": 86399,
    "expired": false,
    "expires_at": 1893456000,
    "binding_mode": "DEVICE",
    "remark": "示例卡密",
    "license_type": "自定义类型",
    "heartbeat_required": true,
    "heartbeat_interval_seconds": 60,
    "heartbeat_timeout_seconds": 180
  }
}

remaining 为剩余秒数，expires_at 为 Unix 秒级到期时间（-1 表示无限）。绑定校验使用卡密当前模式：NONE、IP、DEVICE 或 IP_AND_DEVICE，请结合返回的 binding_mode 处理。

# 心跳验证

应用启用心跳时，根据验证成功响应中的 heartbeat_required 和间隔/超时配置，调用 POST /api/v1/client/license/heartbeat。心跳同样提交公共字段和卡密/设备业务字段，并按应用要求进行签名和编码。每次请求更新 timestamp、nonce；心跳失败后应停止使用授权功能。

# 前后端地址与 OAuth

前端可访问地址用于邮件、通行密钥来源及 OAuth 完成后的返回页面。后端可访问地址用于第三方回调，例如：
https://api.example.com/api/v1/auth/connect/callback/github

登录结果使用短时一次性票据与浏览器持有的验证器交换，不依赖跨站 Cookie。分域访问需配置允许的前端来源及前端运行时 API 地址；不要在客户端存放第三方 Client Secret。
